## 書き出しの方法(縦横比を崩していない)

- 元画像 1672×941 は、ほぼ16:9(実際は約1.7768。16:9は約1.7778)。
- **引き伸ばしはしていない。** 中央寄りに 1664×936(ちょうど16:9)を切り出した
  (左右を各4px、上を2px・下を3px切り取り。地平線と右上の暗色領域は維持される)。
- その 1664×936 を 1920×1080 へ拡大した(倍率 約1.154。GdkPixbufの `HYPER` 補間)。
  元画像より情報量が増えるわけではないが、倍率が小さいため、粗さは目立たない範囲と見ている
  (実機・VMの画面では未確認)。
- **4K(3840×2160)版は作っていない。** 元画像の横幅が1672pxしかなく、4Kにするには約2.3倍の
  拡大になる。拡大しても細部は増えず、ぼやけるだけなので作らないと判断した。
  4K表示の画面では、1920×1080がそのまま拡大表示される。

## 画面への表示

Openbox起動時に `hsetroot -cover` で表示する(`config/includes.chroot/etc/skel/.config/openbox/autostart`)。
`-cover` は、画像の縦横比を保ったまま画面を覆う大きさに拡大し、中央に配置する(はみ出す部分は切り取られる)。
hsetrootのオプションは、Debian 13の `hsetroot` 1.0.5 のmanページで確認した。名前が紛らわしいが、
`-fill` は「縦横比を無視した引き伸ばし」であり、使っていない。

16:9でない画面では、左右(または上下)が切り取られる。1366×768(16:9)・1280×800(16:10)・
1024×768(4:3)の仮想画面で `-cover` の表示を確認した結果は、次のとおり。

- 1366×768: 全体がそのまま拡縮表示される。
- 1280×800 / 1024×768: 縦横比は保たれ、左右が切り取られる(引き伸ばしは起きない)。

## Conky右上領域との関係(計算値・限界あり)

Conkyは右上に、白文字と灰色ラベルで表示される(背景透過、影や縁取りなし。`conky.conf`)。
幅262px+右余白16px、約28行。**高さは実測しておらず、上から約560pxと見積もった。**
下の表は、画素から計算した背景の輝度に対する、白(#ffffff)と灰(#bebebe)のコントラスト比である
(目安は4.5以上)。「最小」は領域内の最も明るい画素での値で、細い光の線1本でも最小値が下がる。

| 表示環境 | 対象領域 | 白文字の最小比 | 灰ラベルの最小比 | 4.5未満の画素(白 / 灰) |
|---|---|---|---|---|
| 1920×1080(書き出しファイルで計算) | x≥1630, y<560 | **7.41** | 3.99 | 0% / 0.01% |
| 1366×768(hsetrootの実表示を取得して計算) | x≥1076, y<560 | 1.29 | 1.44 | 0.90% / 5.99% |
| 1280×800(同上) | x≥990, y<560 | 1.23 | 1.51 | 4.41% / 18.73% |
| 1024×768(同上) | x≥734, y<560 | 1.24 | 1.50 | 32.26% / 61.33% |

読み方:
- **1920×1080では、右上領域の全画素で白文字が4.5以上**(最小7.41)。灰ラベルもほぼ全域で足りる。
- 画面が小さい・4:3に近いほど、Conkyの範囲が壁紙の下半分(地平線や明るい光の筋)に届き、
  読みにくい箇所が増える。**特に4:3(1024×768)は不十分な可能性が高い**(白文字でも3割強の画素が4.5未満)。
- 1366×768では、大半の画素は暗いが、地平線の細い明るい線と光の筋がConkyの下側に重なる。
- この壁紙は16:9を主対象とした構図で、4:3画面への最適化はしていない。

**未確認:** 実機・VMでConkyを重ねた目視確認、Conkyの実際の描画範囲。
